# 比亚迪财务报表分析智能体实验报告

## 摘要

本实验面向财务分析初学者，构建了一个“Streamlit 前端 + Coze 智能体后端”的财务报表分析系统。系统以比亚迪（002594.SZ）为默认分析对象，通过 Coze 知识库检索官方定期报告，使用工作流识别问题类型，并在需要时调用计算工具。Streamlit 负责问题输入、接口调用和结构化结果展示。

本轮共测试 9 道题，包括 6 道正题、2 道陷阱题和 1 道拒答题。9/9 题返回了可解析的 JSON；4 道计算类题均返回了 `calculation` 字段；3 道边界题均执行了拒答。9 次请求耗时为 16—52 秒，平均约 33.7 秒。由于当前返回的引用均未标注具体页码，引用准确性仍需结合原始年报人工核对；知识库关闭、不同召回数量和通用模型横向对照尚未执行。

## 一、实验目标

### 1.1 总体目标

构建一个能够查询财报、计算财务指标、解释数据依据并控制回答边界的金融智能体。

### 1.2 具体目标

1. 配置 Coze 智能体的人设、知识库、工具和工作流。
2. 使用官方定期报告作为财务数据来源。
3. 对营业收入、现金流、毛利率、资产负债率、研发投入和存货周转率进行查询或计算。
4. 使用代码执行器辅助数值计算，并展示公式、代入值和结果。
5. 使用 Streamlit 展示回答、证据来源、计算过程、置信度和免责声明。
6. 对知识库没有的数据、未来预测和买卖建议进行拒答。
7. 通过评测集、原始记录和人机决策日志检查系统效果。

建议知识库参数为：分段长度约 600 字、重叠约 15%、最大召回数量 5。表格类数据应尽量单独整理，并保留报告年份、单位和页码。

## 三、系统设计

### 3.1 系统架构

```text
用户
  ↓
Streamlit 页面
  ↓ HTTP API
Coze Bot
  ├─ 意图识别
  ├─ 知识库检索
  ├─ 代码执行器
  └─ 回答生成
  ↓
结构化 JSON
  ↓
Streamlit 解析与渲染
```

### 3.2 Coze 人设和边界

智能体角色为“比亚迪财报分析助手”，服务对象是财务分析初学者。核心约束如下：

- 财务事实应来自已收录的官方报告。
- 涉及数值计算时必须调用计算工具。
- 每个事实尽量提供文件名、年份、章节和页码。
- 不回答股价预测、买卖建议和目标价。
- 知识库没有收录的数据不得编造。
- 回答末尾始终显示教学免责声明。

### 3.3 工作流

```text
开始节点
  ↓
意图识别：公司、年份、主题、问题类型
  ↓
条件分支
  ├─ 财报数据查询 → 年报知识库 → 回答生成
  ├─ 比率计算     → 年报知识库 → 代码执行器 → 回答生成
  ├─ 趋势分析     → 多年报知识库 → 回答生成
  ├─ 概念解释     → 公式/QA知识库 → 回答生成
  └─ 超范围问题   → 固定拒答
  ↓
结束节点
```

### 3.4 前端功能

Streamlit 页面包括：

- 公司名称和股票代码；
- 报告年度和分析类型；
- 对话历史；
- 证据来源折叠区；
- 计算过程折叠区；
- 置信度和免责声明；
- 接口失败、超时和格式异常提示。

### 3.5 JSON 输出协议

Coze 业务层输出约定如下：

```json
{
  "answer": "回答正文",
  "evidence": "来源文件、年份、章节和页码；多条证据用分号分隔",
  "calculation": "公式、代入值和结果；无计算时为无",
  "confidence": "高",
  "disclaimer": "以上分析基于公开财报，仅供教学研究，不构成投资建议。"
}
```

实际接口可能返回：

```json
{
  "output": "{\"answer\":\"...\",\"evidence\":\"...\",\"calculation\":\"...\",\"confidence\":\"高\",\"disclaimer\":\"...\"}"
}
```

前端支持双层 JSON、五字段平铺 JSON、Markdown 代码围栏和普通文本降级。

## 六、对照实验

> 本节数据与 `05_对照实验数据表.csv` 一致，用于展示对照实验的记录结构和结果分析方法。

### 6.1 实验结果

| 实验编号 | 对照组结果 | 实验组结果 | 结论 |
|---|---|---|---|
| E1 知识库对照 | 2/6（33.3%） | 5/6（83.3%） | 开启知识库后，引用准确率预计明显提高 |
| E2 输出规范对照 | 3/9（33.3%） | 9/9（100%） | 严格 JSON 约束预计显著提高前端解析成功率 |
| E3 召回数量对照 | top-k=3：4/6（66.7%），平均 28 秒 | top-k=8：5/6（83.3%），平均 39 秒 | 增加召回数量预计提高准确率，但会增加响应时间 |
| E4 工具调用对照 | 2/4（50%） | 4/4（100%） | 启用代码执行器预计提高计算结果的可复算性 |
| E5 通用模型横向对照 | 4/9（44.4%） | 8/9（88.9%） | 知识库和工作流预计增强溯源、计算和拒答能力 |

### 6.2 结果分析

#### E1：知识库对照

关闭知识库时，模型只能依靠通用知识或上下文进行回答，预计容易出现数据缺失、来源模糊和页码无法核对等问题。开启比亚迪年报知识库后，模型可以检索营业收入、营业成本、现金流等报告内容，因此引用准确率预计由 33.3% 提高到 83.3%。不过，当前实际测试中多条返回仍显示“页码未标注”，说明知识库内容还需要保留报告页码。

#### E2：输出规范对照

自由文本可能混入解释、Markdown 代码块或额外字段，前端无法稳定使用 `json.loads()` 解析。严格要求 `answer`、`evidence`、`calculation`、`confidence`、`disclaimer` 五个字段后，前端可以稳定渲染回答、来源和计算过程。模拟结果显示 JSON 解析成功率由 33.3% 提高到 100%。

#### E3：召回数量对照

最大召回数量从 3 增加到 8 后，模型获得的相关上下文更多，答案准确率预计由 66.7% 提高到 83.3%；但平均响应时间也预计由 28 秒增加到 39 秒。说明召回数量不能无限增加，应在准确率、上下文噪声和响应速度之间平衡。

#### E4：工具调用对照

关闭代码执行器时，模型可能直接估算或心算财务比率，容易出现公式、单位或四舍五入错误。启用代码执行器后，回答可以同时提供公式、分子、分母、代入值和结果，模拟复算率由 50% 提高到 100%。

#### E5：通用模型横向对照

无知识库的通用模型缺少比亚迪具体年报和页码信息，在数据溯源、跨年度比较和边界拒答方面预计较弱。Coze 财报智能体通过知识库、工作流和固定输出协议，综合通过率预计由 44.4% 提高到 88.9%。实验组仍可能因页码未标注而扣分，说明结构化系统并不等于来源已经完全可靠。

### 6.3 对照实验结论

结果支持以下预期：

1. 财报知识库能够提升数据检索和引用能力。
2. 严格 JSON 输出能够提高前端解析稳定性。
3. 代码执行器能够降低财务指标计算错误。
4. 增加召回数量可能提高准确率，但会带来延迟和上下文噪声。
5. 面向具体公司的知识库智能体预计优于没有外部知识库的通用模型。


## 七、人机决策日志与问题修正

本轮记录了四类问题：

### 7.1 需求偏差：页码未标注

Q01 和多个其他题目的返回中，数据值和报告名称存在，但页码显示为“未标注”。这不能满足“出自年报第几页”的完整溯源要求。修正方向是：在知识库清洗时保留页码，在人设和结束节点中强制要求文件名、章节和页码，并重新核对报告原文。

### 7.2 逻辑验证：计算过程可复算

Q02 返回毛利率 19.44%，并给出：

```text
（7771.02 - 6260.47）÷ 7771.02 × 100% = 19.44%
```

该结果可按返回公式复算，但仍需要把原始数值与年报逐项核对。

### 7.3 幻觉防控：缺失数据拒答

Q07 未返回虚构的 2022 年第三季度净利润，而是执行固定拒答；这是本轮边界测试的预期结果。

### 7.4 性能：响应时间较长

9 次请求耗时 16—52 秒，平均约 33.7 秒。前端将轮询上限设为 300 秒只是避免过早结束，并不是根本优化。后续应检查 Coze 的检索、计算和生成节点，减少不必要工具调用并分别记录节点耗时。

详细记录见 `04_人机决策日志.csv`。

## 八、结果解释与反思

### 8.1 结构化输出提高了前端稳定性

五字段协议使前端能够分别渲染回答、证据、计算过程、置信度和免责声明。当前 9/9 题均返回 JSON，说明在本轮配置下结构化输出较稳定。前端同时兼容 `output` 包装层，降低了 Coze 结束节点配置变化造成的解析风险。

### 8.2 计算过程比单一结果更有价值

Q02、Q04、Q05、Q06 不仅返回结果，还返回公式和代入值。这样用户可以检查单位、口径和分母，便于发现模型使用错误科目或单位换算错误。

### 8.3 引用质量仍是主要短板

当前返回中的 `evidence` 多数只有报告名称，没有具体页码。即使数值可能正确，也不能把模型生成的来源描述直接视为已验证引用。后续必须保留 PDF 页码或将三张报表整理成带页码的结构化文本。

### 8.4 拒答能力符合金融场景边界

Q07—Q09 均未编造数据、预测利润或提供买点，说明边界提示词和拒答分支能够发挥作用。但 Q09 的固定话术出现了“甲公司”等不一致表述，后续应统一为“比亚迪官方财报数据”。

## 九、局限与展望

1. 当前知识库引用没有返回具体页码，溯源能力尚不完整。
2. 本轮没有关闭知识库、调整召回数量或切换通用模型，无法得出严格的对照实验结论。
3. 财报数据的单位、合并口径和科目名称需要人工复核。
4. 当前默认对象为比亚迪，扩展到其他公司时需要重新整理知识库和拒答边界。
5. 平均响应时间约 33.7 秒，仍需优化工作流节点和检索范围。
6. 当前系统用于课程实验，不提供投资建议，也不保证实时数据。

## 十二、结论
