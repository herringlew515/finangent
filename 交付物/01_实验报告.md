## 一、实验目标

### 1.1 总体目标

围绕公司金融场景，完成一个可演示、可评测、可追溯的金融智能体：在 Coze 中完成人设、知识库、工具/插件、工作流与结构化输出配置；使用 Streamlit 调用 Coze API，完成交互界面、引用展开、计算过程展示和错误提示。

### 1.2 具体目标

1. 理解智能体的五要素：人设、知识、工具、工作流和输出规范。
2. 以比亚迪财务报表分析为方向，完成财报问答、财务比率计算和边界控制设计。
3. 在 Coze 中完成 Bot 人设、年报知识库、代码执行器、工作流和 JSON 输出配置。
4. 通过 Coze API 对外调用智能体，并用 Streamlit 完成结构化渲染。
5. 设计至少 8 道评测题，完成知识库、输出格式、召回参数和工具调用的对照分析。
6. 识别人机协作中的幻觉、逻辑 bug、需求偏差和性能问题。
7. 完成包含“翻车—排查”环节的 7 分钟演示。

## 四、系统设计

### 4.1 Coze 人设配置

| 人设四问 | 本组填写 |
|---|---|
| 它是谁？ | 比亚迪财报分析助手，而非通用问答机器人 |
| 服务谁？ | 财务分析初学者和需要快速核对财报的学生 |
| 边界在哪？ | 不提供买卖建议、不预测股价；无依据的数据必须拒答 |
| 输出成什么样？ | 返回 `answer/evidence/calculation/confidence/disclaimer` 五字段 JSON |

核心提示词约束：

- 所有财务数据优先来自已收录的比亚迪官方报告。
- 涉及数值计算必须调用代码执行器。
- 证据应包含报告名称、年份、章节和页码。
- 无可靠数据时使用固定拒答，不返回 0、空对象或猜测值。
- 结尾始终显示教学免责声明。

### 4.2 LLM 辅助配置记录

向 LLM 提问的示例：

```text
请帮我设计一个 Coze 工作流结束节点的 JSON 输出规范，
字段包括 answer、evidence、calculation、confidence、disclaimer，
并兼容财报问答、比率计算和超范围拒答。
```

形成的输出规范：

```json
{
  "answer": "回答正文",
  "evidence": "来源文件、年份、章节和页码；多条用；分隔",
  "calculation": "公式、代入值和结果；无计算时为无",
  "confidence": "高/中/低/未标注",
  "disclaimer": "以上分析基于公开财报，仅供教学研究，不构成投资建议。"
}
```

Coze 实际可能将业务 JSON 放在 `output` 字符串中：

```json
{
  "output": "{\"answer\":\"...\",\"evidence\":\"...\",\"calculation\":\"...\",\"confidence\":\"高\",\"disclaimer\":\"...\"}"
}
```

前端支持双层 JSON、平铺 JSON、Markdown 代码围栏和普通文本降级。

### 4.3 知识库准备

| 材料名称 | 类型 | 年份/日期 | 来源 | 解决什么问题 | 清洗策略 |
|---|---|---|---|---|---|
| 比亚迪年度报告 | 年报 | 2024 | 巨潮资讯网/公司官方披露 | 收入、成本、现金流、资产负债数据 | 去页眉页脚，保留单位和章节；三张表行式整理 |
| 比亚迪年度报告 | 年报 | 2023 | 巨潮资讯网/公司官方披露 | 跨年度趋势比较 | 保留报告年份、科目、单位和页码 |
| 财务比率公式 | QA/方法论 | - | 教材整理 | 毛利率、资产负债率、周转率概念解释 | 按一问一答整理 |

知识库建议参数：

```text
分段长度：约 600 字
分段重叠：约 15%
最大召回数量：5
最小匹配度：默认
```

当前问题：实测返回多次显示“页码未标注”，需要在后续清洗中保留并验证 PDF 页码。

### 4.4 调用的插件/工具

| 工具 | 描述（何时调用） | 参数 | 失败行为 |
|---|---|---|---|
| 代码执行器 | 比率、增长率、差额和单位换算 | 数值型分子、分母、公式类型 | 返回明确错误，不返回 0 或空对象 |
| 知识库检索 | 查询财报原文和财务科目 | 查询词、年份、主题 | 找不到可靠材料时触发拒答 |
| LLM 节点 | 意图识别、回答组织和 JSON 生成 | 用户问题、检索片段、计算结果 | 缺字段时由前端提示格式异常 |

### 4.5 工作流与前端系统架构

```text
开始节点
  ↓
LLM 意图识别：company/year/topic/query_type
  ↓
条件分支
  ├─ 财报问答 → 年报知识库 → 回答生成
  ├─ 比率计算 → 年报知识库 → 代码执行器 → 回答生成
  ├─ 趋势分析 → 多年报知识库 → 回答生成
  ├─ 概念解释 → QA 知识库 → 回答生成
  └─ 超范围 → 固定拒答
  ↓
结束节点：五字段 JSON
```

Streamlit 端负责：

1. 读取公司、代码、年度和分析类型；
2. 组合用户问题；
3. 通过 `requests.post` 调用 Coze；
4. 轮询 `conversation_id` 和 `chat_id`；
5. 解析 `answer/evidence/calculation/confidence/disclaimer`；
6. 渲染卡片、展开引用、计算过程和错误提示。

提交时应补充 Coze 工作流截图和 Streamlit 运行截图。

## 五、实验过程

### 5.1 关键决策记录

1. **从通用助手转为财报分析助手**：为了让评测可聚焦，将公司范围默认设为比亚迪，并增加“不预测股价、不提供买点”的边界。
2. **前后端解耦**：规定 Coze 输出五字段 JSON，Streamlit 只负责解析和展示。
3. **兼容双层 JSON**：实际 Coze 返回存在 `output` 字符串包装，因此前端增加二次解析。
4. **计算过程必须可复算**：不只显示结果，还要求返回公式、分子、分母、单位和代入值。
5. **性能问题不靠无限延长等待解决**：前端保留超时上限，性能优化应回到 Coze 检索和工作流节点。

### 5.2 人机决策日志摘录

| 题号/任务 | 输出或现象 | 怀疑点 | 错误类型 | 验证与修正 |
|---|---|---|---|---|
| Q01 | 收入约 7771.02 亿元，但页码未标注 | 无法完整溯源 | 需求偏差 | 要求知识库保留页码，并在结束节点强制输出来源 |
| Q02 | 毛利率 19.44%，包含公式和代入值 | 需要确认口径和手算一致 | 逻辑验证 | 复核 `(7771.02-6260.47)/7771.02`，结果可复算 |
| Q07 | 对缺失数据执行固定拒答 | 是否会编造数值 | 幻觉防控 | 检查 answer、evidence 和 calculation，未发现虚构数据 |
| Q01-Q09 | 单题耗时 16—52 秒，平均约 33.7 秒 | 工作流响应偏慢 | 性能 | 记录开始/结束时间，后续拆分 Coze 节点耗时 |

## 六、对照实验结果

> 以下 E1—E5 结果与 `05_对照实验数据表.csv` 一致，是学习用途的模拟示例，用于展示结果结构和分析方法；Q01—Q09 的基础实验组结果来自实际原始记录。

### 6.1 对照实验设计

- E1：知识库关闭 vs 开启，测引用准确率。
- E2：自由文本 vs 严格 JSON，测解析成功率。
- E3：最大召回数 3 vs 8，测准确率和响应时间。
- E4：关闭 vs 开启代码执行器，测计算复算率。
- E5：无知识库通用模型 vs Coze 财报智能体，测综合通过率。

### 6.2 实验数据表

| 编号 | 对照组结果 | 实验组结果 | 结论 |
|---|---|---|---|
| E1 | 2/6（33.3%） | 5/6（83.3%） | 知识库预计提升引用准确率 |
| E2 | 3/9（33.3%） | 9/9（100%） | 严格 JSON 预计提升解析稳定性 |
| E3 | top-k=3：4/6（66.7%），平均 28 秒 | top-k=8：5/6（83.3%），平均 39 秒 | 召回增加预计提高准确率，但增加延迟 |
| E4 | 2/4（50%） | 4/4（100%） | 代码执行器预计提高复算率 |
| E5 | 4/9（44.4%） | 8/9（88.9%） | 知识库和工作流预计提高综合表现 |

### 6.3 核心横向对照

| 对比维度 | 通用模型/对照组 | Coze 财报智能体/实验组 |
|---|---|---|
| 数据溯源 | 缺少比亚迪私有报告和页码 | 可检索报告，当前页码仍需补充 |
| 计算逻辑 | 可能口算或混淆口径 | 代码节点输出公式和代入值 |
| 边界控制 | 可能强行回答 | 通过人设和分支拒答 |
| 输出结构 | 自由文本 | 五字段 JSON，可直接渲染 |

### 6.4 对照结论

模拟结果预计表明：知识库提升财报数据溯源能力；严格 JSON 提高前端稳定性；代码执行器提高计算可复算性；增加召回量在提高准确率的同时增加延迟；面向具体公司的金融智能体整体优于无外挂知识的通用模型。

## 七、结果解释与反思

### 7.1 实测结果解释

本轮 Q01—Q09 中，9/9 题返回可解析 JSON，4/4 计算题返回 `calculation`，Q07—Q09 均执行边界控制。Q02 返回毛利率 19.44%，并给出营业收入、营业成本、公式和代入值，具备复算条件。Q03 返回经营活动现金流净额约 1334.54 亿元、投资活动现金流净额约 -1290.82 亿元。

### 7.2 金融视角反思

金融分析不能只看模型是否给出数字，还要看数字的口径、单位、来源和可复算性。知识库可以降低数据缺失风险，但如果页码没有保留，答案仍然不够可审计。代码节点适合执行算术，模型则更适合组织解释和总结。对没有依据的问题，正确的结果不是“尽量回答”，而是明确拒答。

### 7.3 LLM 的适用边界

LLM 适合做资料摘要、意图识别、公式说明和回答组织；不应独立决定数据口径、核心估值假设或投资建议。财务数据必须回到报告原文，计算必须通过公式和工具验证，结论必须保留假设和局限。

## 八、局限与展望

### 8.1 当前局限

1. 当前返回多次出现“页码未标注”，引用尚未达到逐条可核对的要求。

6. Streamlit 适合课程演示，尚不具备专业金融终端的多图联动能力。

## 结论

本实验完成了“用户—Streamlit—Coze—知识库/工具/工作流—结构化 JSON—Streamlit 渲染”的基本链路。实测结果证明，当前系统可以稳定返回结构化结果、展示计算过程并执行边界拒答；同时，页码溯源、对照组真实性和响应速度仍是主要改进方向。金融智能体的核心价值不是对所有问题作答，而是在有依据时可追溯、需要计算时可复算、没有依据时能拒答。
